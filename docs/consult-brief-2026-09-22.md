# 2. これまでの経緯（ここが相談の背景）

## 2-1. 最初の設計と、その崩壊

当初の設計はこうだった。

1. QRを読む → 5段階評価
2. **★4〜5** → AIが書いたクチコミの下書きをコピーして Google マップへ
3. **★1〜3** → 店内向けの改善アンケートへ分岐（＝低評価を公開レビューに出さない）

これは業界でよくある形で、洋輔の温度感も「グレーぎりぎりを攻めたい、★1〜3にはなるべく Google への案内を出したくない、でもアカウントのBANは避けたい」だった。

2026年8月、Googleのポリシー原文を読み直して、**この★分岐そのものが禁止条項に真正面から当たる**と分かった。

> 原文：「顧客からの否定的なクチコミの投稿を妨げたり禁止したり、**肯定的なクチコミを選択的に募ったり**する行為」

罰則は段階的で、最悪は「**偽レビューが削除されたことを消費者に知らせる警告バナーが、店のGoogleマップのページに表示される**」。来店を検討している人から見える形で出るので、店にとっては致命傷になる。

なお、業界のブログには「2026年4月17日にGoogleが規約を改定した」と書かれているが、**これは誤り**だと確認した（Internet Archive でGoogleのページを遡って機械的に照合した）。正しくは「**2026年2月に条文が追加され、4月16日に執行と検知が強化された**」。4月に条文は1文字も変わっていない。

## 2-2. 思想を言語化し、★分岐を捨てた

私が言語化して、洋輔が承認した思想がこれ。

> **選別することなく、選択させる。**
> 良かったことはGoogleへ、気になったことはお店へ。**店が選り分けるのではなく、お客さんが選ぶ。**

具体的な形（「案I」と呼んでいる）は、**全員が同じアンケートを書き終えたあと、「この感想をどうしますか？」で宛先を本人が選ぶ**というもの。2枚のカードは同じ大きさ・同じ書式で、どちらが良いとは一切書かず、「誰が読むか」だけを書く。

- 「地図に公開されます」
- 「店長が直接読みます」

**扉の文言に感情の向きを紐付けた瞬間にアウト**（「ご不満の方はこちら」は違反）というのは、恒久の設計ルールにした。

このとき、洋輔の「★1〜3には案内を出したくない」という不安には、海外の実データで答えた。米国の GatherUp が2018年に、顧客約10,000拠点を強制的に非振り分け方式へ切り替えた前後12か月の比較：

| | Googleレビュー件数 | 平均星 |
|---|---|---|
| 振り分けあり | 32,689件 | 4.66 |
| 振り分けなし | 53,790件 | **4.59** |
| 差 | **+68%** | **▲0.07** |

**件数は7割近く増え、星は0.07しか下がらない。**

## 2-3. ところが、本当に危ないのは別のところだった

ポリシーをもう一段細かく読むと、店舗を名宛人とする条項が**2つの層**に分かれていた。

- **層1「誰に頼むか」** ＝ ★での振り分け（review gating）の話
- **層2「何を書かせるか」** ＝ 「インセンティブを提供したり、**評価やクチコミの内容に影響を与えようとしたり**せずに」「**特定の内容を含めるよう求めてもならない**」

**★の振り分けをやめることは、層1には完璧に効くが、層2のリスクを1ミリも減らさない。**
AIが完成した文章を提示して、来店客がそれをコピーしてGoogleに貼る——この形は「店舗側が内容に影響を与えた」と評価されうる領域にある。

つまり、**AI下書き機能が残る限り、そこが唯一かつ最大の論点だった。**

日本の景品表示法（ステマ規制）にも刺さる論点がある。消費者庁の運用基準の原文に、こう書いてある。

> 「当該事業者（**当該事業者から委託を受けた仲介事業者を含む。**）と当該購入者との間で、当該購入者の投稿（表示）内容について情報のやり取りが直接又は間接的に一切行われておらず」

**つまり、私のツールの画面が来店客にやったことは、法的には「店舗自身がやったこと」として評価される。**「ツールが自動でやっただけ」という切り分けは条文上成立しない。製品仕様そのものが、契約店舗の法的リスクを決めてしまう。

実際に処分事例もある（令和6年6月6日、医療法人社団祐真会への措置命令。Googleマップに★4以上を投稿することを条件にワクチン接種費用を割引していた事案）。

## 2-4. そして、実害が出た

2026年8月、洋輔の店の1つが、**第三者から「AIっぽい文章が並んでいる＝ステマではないか」と指摘された**（FROMAという媒体で書かれた）。

原因は構造的なものだった。実装を調べたら、AIに渡している材料は「**★4か★5か ＋ 選んだタグ**」だけで、自由記述はほぼ空。つまり実際の入力パターンは10通り程度に収れんする。実際にAPIを5回叩いて測ったら、5件とも「スタッフ → 料理 → また来たい」で骨格が同一、類似度（3文字組の重なり）は中央値0.32だった。

さらに、査読済みの研究（Science Advances, 2024）が、**生成AIのアイデアを与えられた書き手の作品は、互いに似てくる**ことを示している。**プロンプトを磨いても、この構造は消えない。**

そして米国の調査では、**46%の消費者が「レビューがAIが書いたように見えたら偽レビューだと疑う」**と答えている。

**この「ステマと書かれた文章」は、今この瞬間も洋輔の3店舗で出続けている**（本番のプロンプトは今も「★5のときは『また来たい』という気持ちを自然に含める」と指示している。同じ入力で3回生成したら3回とも「また来たい」が出て、うち2回は回答に無い事実を捏造した）。

## 2-5. 「AIは助詞だけ」まで削った（v4）

9月に方針を変えて、**AIの役割を「本人が書いた文に、助詞と句読点を足して1文にする」だけに降ろした**プロトタイプを作った。全文生成は廃止。

| 本人が書いた文字列 | AIが返した1文 |
|---|---|
| 店員さん 説明ていねいだった | 店員さん**の**説明**が**ていねいだった**。** |
| 値段ちょっと高い でも量おおい | 値段ちょっと高い**でも**量おおい**。** |

AIの出力を機械で検査する層も作った（削除を認めない・挿入はひらがな2文字まで・敬体化の禁止・空白の挿入禁止・似すぎ検出）。作ったあとに「検査層を破りにいく」レビューを34エージェントでかけたら、**18件の穴が実際に再現した**。いちばん重かったのは「よかった」→「よ**くな**かった」が検査を通っていたこと（ひらがな2文字で意味が反転できた）。全部塞いだが、**これは守り続けないといけない装置**になった。

## 2-6. 競合の状況（2026年9月時点の調査）

**A群：アンケート→AIが口コミ本文を書く（＝いま私がいる土俵）**

| 製品 | 価格 | AIの位置づけ |
|---|---|---|
| Revimy | ミニ 9,800円/月（税抜） | 中心機能。30秒アンケート→AIが下書き |
| キキコミ | 非公開。最低6ヶ月 | 中心機能。gating非実装を利用ガイドラインで明文化 |
| AskTap | 9,000円/月（税別）〜 | 中心機能。2026年8月に新規参入 |
| MEO CHEKI REVIEW byGMO | 11,000円〜 | 「タップするだけでクチコミが生成される」 |
| 口コミロボ | 非公開 | 中心機能 |

**わかったこと3つ。**

1. **「★で振り分けません」は、もう旗にならない。** キキコミが利用ガイドラインに逐語で「ゲーティングに相当する機能は実装されていません」と書いている。**参入条件になった**
2. **価格では差別化できない。** 9,800円は Revimy と完全に同額
3. **国内のAI型は、ほぼ全社が「AIが文章を書きます」を主訴求にしている。** 逆に「**本人が書くことを初期状態に置く**」製品は、調べた範囲では国内に見つからなかった（※「見つからなかった」は「存在しない」の証明ではない）

海外では、業界最大手の Birdeye がこう線を引いている。

> 「AIが自動でレビューを生成して、実際の顧客が書いたかのように投稿するのは**倫理的な一線を越える**。ただし、**顧客が自分の考えをより明確に表現するのを助ける**ためにAIを使うのは、信頼を損なわない」

## 2-7. もう1つの日本市場の特徴

日本では、従業員から口コミを依頼されたとき「あまり書きたくない」「絶対に書かない」の合計が **約62%**（n=1,000、2025年2月）。一方、米国の同種調査では「依頼されれば書いてもよい」が **94%**。**日本と米国は正反対。**

**つまり、米国型の「スタッフが口頭で頼む」設計は日本では機能しない。** 卓上POPのQRという「頼まれた感のない入口」は、日本では必然の正解だと考えている。

# 3. 今回、私が考えた方針転換（これを壊してほしい）

ここからが相談の本題。9月22日に私が考えて、明日（9月23日）洋輔と決める内容。

## 3-1. 訴求を「レビューが増えます」から「正当な評価」に置き換える

単に「レビューを増やします」ではなく、「**こういう設計だからこそ、お店が正当な評価を受け取れる**」を売り文句の決め手にしたい。

「正当」には向きの違う2つの意味がある、と整理した。

| 誰にとっての正当か | 中身 | いまの形の何が足りないか |
|---|---|---|
| Googleに載る評価 | **本物性** — 載っているのが本人の言葉であること | AIが書いた文をコピーして貼る。第三者に見抜かれた |
| お店が受け取る評価 | **代表性** — 声の大きい人だけでなく、来た人全体の姿が見えること | ★と数個のタグだけ。何を直せばいいか分からない |

**この2つを1本の流れでやろうとしていたことが、いままでの無理の正体だった**と考えている。

## 3-2. AIによる口コミ下書きを、完全に廃止する

v4で残していた「助詞と句読点だけ足す」も含めて、**表側からAIを全部外す**。

代わりに置くのは、この1行だけ。

> **文章を書かなくても、★だけで投稿できます。**

★だけで投稿できることを知らないユーザーが多いので、その案内でハードルを下げる。文章は書きたい人だけが、Googleマップの投稿欄で自分で書けばいい。

**やめると、守り続ける必要があったもの（検査層・プロンプトの承認と保守・API費用・レート制限）が丸ごと消える。**

## 3-3. AIは「表」ではなく「裏方」で使う

見やすさやUIデザイン、価格勝負では他社に勝てない。MEO対策としての口コミ返信機能なども他社にある。**それ以上のオリジナリティが必要。**

だから目玉のAI機能は、来店客に見える表側ではなく、**店舗側の業務改善・マーケティング支援**で走らせる。

## 3-4. Googleクチコミと「アンケート」を、明確に分離する

- **Googleクチコミの扉**：評価したい人が★を付ける／投稿する。それだけ
- **アンケートの扉**：Googleとは完全に無関係。**回答特典**（ドリンク1杯無料、チーズケーキなど。付けるかどうかは店の自由）を付けられる

アンケートは**お客さんが文章を書くのではなく、選択肢をタップしていくだけで1〜2分で楽しく終わるUI**にする。聞く内容は、性別・地域・来店回数・味・雰囲気・接客など。

**分離の本当の狙いは、特典ではない。**（ここは相談の相手であるあなたに特に見てほしい）
消費者庁の運用基準が「投稿内容について**間接的にも**やり取りがないこと」を条件にしている以上、**店やAIが作った問いを、Google投稿と同じ流れで見せると、その「間接的なやり取り」に読まれうる。**
分離すると、この問題が構造ごと消えて、**アンケート側では何を聞いてもよくなる。**

## 3-5. AIが、半自動で「何を聞くか」と「どう活かすか」を埋める

店舗側は「何を質問すべきか」「その結果をどう改善に活かすか」が分からないことが多い。そこをAIが埋める。**全自動ではなく、お店の要望を聞き出しながら、次の施策や分析レポートを提示する。**

順番はこう考えている。

| 段 | 何をするか | 動き出す条件 |
|---|---|---|
| ① 問いの提案 | 業態・目的・メニューから、アンケートの問いのセットを出す。店が選んで確定 | **データ0で動く** |
| ② 読み解き | 溜まった回答から次の打ち手を出す（「木曜の夜だけ接客の評価が落ちる」） | 1店舗あたり数十件 |
| ③ 注文履歴と突き合わせ | GOOD ORDER の「実際に何を注文したか」を問いの材料にする | 注文SaaSとの連携 |

③は、**注文SaaSを自社で持っていないと作れない**ので、競合が構造的に真似できない部分だと思っている。ただし現時点で1行も実装していない。

## 3-6. 見せ方

「GOOD REVIEW」という1つのプロダクトの中に、

- Googleクチコミを増やしたい人向けの機能
- アンケートを集めてマーケティングに活かしたい人向けの機能

が統合されつつも、**前面に出す主体は「マーケティングツール」という見せ方**にするのはどうか、と考えている。

# 4. すでに私が気づいている穴（ここも潰してほしい）

自分で気づいた分は先に出す。**これ以外の穴を見つけてほしい。**

1. **特典のある扉は、Googleの扉を飢えさせる。** 良い評価の人も特典側を選ぶ。洋輔の目的（Googleの件数）に直撃する。いまの対策案は「特典は店舗設定でON/OFF、既定はOFF」「Googleの扉はアンケートの後に一度も出さない」の2つ。これで足りるか？
2. **裏方AIはデモで見せにくい。** 「タップしただけで文章ができた」は営業でいちばん効く瞬間だった。それが消える
3. **②の読み解きはデータが要る。** 実データ12行では空の画面になる
4. **「他になかった」はまだ言えない。** 競合調査は口コミツールとMEOツールだけで、**店舗アンケート×AI分析の土俵は調べていない。** 特にLINE公式アカウントの「リサーチ＋クーポン」は無料で使えて、アンケート側の直接の比較相手になる
5. **★だけの投稿が同じ店に束で立ったときの、Google側の扱いが分からない**（一次情報がない）

# 5. 動かせない制約

- **匿名性を壊せない。** いまの回答テーブルは氏名・連絡先・端末IDを一切持たない。だから個人情報保護法の規律が原則発動しない。これは偶然ではなく資産だと思っている。メール・電話・会員IDを足す判断は、法的コストが跳ね上がる意思決定になる
- **Googleの規約と景表法は動かせない。** 特に「委託を受けた仲介事業者を含む」がある以上、製品仕様がそのまま店舗の法的リスクになる
- **開発リソースは実質1人**（私＋AI）。洋輔は店舗の運営と現場の知見担当
- 9月末〜10月上旬に「危険を消すリリース」、11月に「売り始めるリリース」を置いている

# 6. 聞きたいこと

**褒めなくていい。賛成が要るわけではない。穴と、もっと良い形が知りたい。**
以下に順番を付けたが、あなたが「もっと重要な論点がある」と思うなら、それを先に書いてほしい。

1. **3-4（Googleとアンケートの分離）は、本当に成立するか。** 特典のある扉がGoogleの扉を飢えさせる問題について、私の2つのルール（店舗設定でON/OFF・Googleの扉を後に出さない）より良い解き方はあるか。そもそも同じQR・同じ入口に2つの扉を置くのが正しいのか（例：QRを分ける、POPを分ける、タイミングをずらす、など）

2. **3-2（AIを表から完全に外す）は、やりすぎではないか。** 私はこれで正しいと思っているが、**反対の立場から最も強い反論**を出してほしい。「書きたいけど書けない人」を捨てることになるが、そのコストをどう見積もるべきか

3. **アンケートに特典を付けると、回答の質はどうなるか。** 特典目当てで適当にタップされたデータは、②の読み解きの材料として使い物になるか。防ぎ方はあるか
