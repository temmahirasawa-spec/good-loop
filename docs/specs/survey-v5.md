## 1. 一文の定義

> **全員が答えるのは★と話題の2問だけ。書きたい人にだけ、選んだ話題ごとの欄を渡す。
> AIは書いている途中には出てこず、最後に各欄の言葉を「つなげる」だけ。AIが足した文字には色を付けて見せる。**

## 2. 決まったこと

### 2-1. 2026-09-26 の5つの決定（壁打ち資料 §8）

| # | 論点 | 決定 |
|---|---|---|
| 1 | ★だけの強調をどこでするか | Googleの扉の中で行う（2枚の扉は同じ形・同じ強さ） ※下の実機所感で「文章も書く」が塗りボタンに変わった |
| 2 | 書く画面のAI | 聞く＋整える＋話す（標準） ※下の実機所感で「聞く」を外し、「整える」を「つなげる」に置き直した |
| 3 | 例の予測変換 | 入れない |
| 4 | 来店客の画面で「AI」と名乗るか | 名乗る（いまは「つなげる」画面の「AIがつなげました」バッジ） |
| 5 | お店にだけの扉にも書く画面を置くか | 置く（書く画面は1つ、届け先だけ違う） |

| 所感 | 反映 |

## 3. 画面と流れ

```
① 評価（★を5つ横に並べて、タップで塗る。塗られたのを見てから自動で次へ）
② 話題（当てはまるもの・いくつでも・選ばなくても進める）→［次へ］
③ 届け先（2枚の扉。同じ大きさ・同じ形・同じ言い方。並び順は★によらず固定）
     ┌ Googleマップに投稿／だれでも読めます ┐   ┌ お店にだけ届ける／お店の人だけが読みます ┐
     │［文章も書く］（塗り）                │   │［文章も書く］（塗り）                     │
     │［★だけで投稿する］（線）              │   │［このまま届ける］（線）                   │
     └───────────────────┘   └─────────────────────┘
④a ★だけ：あなたの評価 ★★★★☆ ／ Googleの画面で★を選んで「投稿」を押すと完了です →［Googleマップを開く］
④b 書く画面：選んだ話題の数だけ欄（料理について／接客について…）。話題を選ばなかったら「今日のこと」の1欄
     →［AIでつなげる］（何も書かなければ［Googleマップを開く］／［お店にとどける］）
④b' つなげる：各欄の言葉をAIが1つずつ整えてつなげる。AIが足した文字に色。元の言葉のまま／直す
     →［コピーしてGoogleを開く］／［お店にとどける］
④c お店へ（このまま）：お店にとどく内容（★・選んだこと）→［とどける］
⑤ 完了
```

**タップ数（v4 と同じ数え方）**

| 経路 | タップ数 |
|---|---|
| ★だけでGoogleへ | 4（★・次へ・★だけで投稿する・Googleマップを開く） |
| そのままお店へ | 4（★・次へ・このまま届ける・とどける） |
| 書いてGoogleへ／書いてお店へ | 5＋書く操作（★・次へ・文章も書く・AIでつなげる・コピーしてGoogleを開く／お店にとどける） |

**④b 書く画面**

- 欄は②で**選んだ順**に並ぶ。欄の名前は「料理について」のように**話題だけ**を書く
  （「料理で良かった点」だと★が低い人が書きにくい。8/28 に「★で問いを変えない」と決めたのとも合わせた）
- 欄のプレースホルダは v4 の**静的な問い**（話題ごとに3問を回す）。**AIは一度も呼ばない**
- 空いている欄があってよい。注記：個人が特定できることは書かない／（Googleのとき）書いた文章は、お店にも届きます

## 4. つなげる（AIの役割はここだけ）

- 書いた欄を**1つずつ並列で**「整える」AI（v4 の `/api/survey/polish`）に渡す。渡すのは**その欄の文字列だけ**（★・話題・店名は渡さない）
- 返ってきた1文は、v4 の検査層（`lib/survey/polish-guard.ts`）を**サーバー側で**通ったものだけ。
  AIが足せるのは許可した助詞と句読点だけで、本人の文字を消す・並べ替える・言い換える・語尾を変える、はすべて捨てられる
- 検査に落ちた欄・通信に失敗した欄は、**本人の言葉のまま**（句点だけ足す）でつなげる。1つもAIが整えられなければ「AIがつなげました」とは出さない
- **AIが足した文字に色を付ける。** 本人の文字列とAIの出力の最長共通部分列（`lib/survey/insertions.ts`）を取り、そこに入らない文字＝AIが足した文字
- 「元の言葉のまま使う」でいつでも戻せる。「直す」で本人が編集した時点で、その文が最終版になる（色は消える）
- Googleのときは「あなたの評価 ★★★★☆」と「Googleの画面で★を選び、文章を貼り付けて『投稿』」を添える。
  **「同じ数の★を選んでください」とは書かない**（Googleでの評価の中身に触れないため）

## 5. 実測（2026-09-26、/demo/v5 を検品用ビルドで実際に操作）

改訂版の実測は §5-2。改訂前（問いを返すAI）の実測は記録として §5-1 に残す。

### 5-1. 改訂前：問いを返すAI（外した）

- 最初の問いは最後の入力から約2.5〜2.8秒。例「今日は天気が良く窓際の席だったので」→「窓からはどんな景色が見えましたか？」
- 10秒止まると別の角度の問いに替わり、さらに10秒で「ここまでで投稿できます」
- 直したこと：問いが30字を超えて捨てられる／「何か参考になったことはありますか？」「何か行動に移しましたか？」（良い前提・実質はい／いいえ）
- 残った課題：「その船はどのくらいの時間かけて通っていきましたか？」のような細かすぎる問い
- **天真の iPhone 実機での所感：「割り込まれてうっとうしい」「適切な問いとは限らない」→ 外した**

### 5-2. 改訂後：話題ごとの欄＋つなげる

（改訂版の撮影で実測した値は `docs/handoff.md` 2026-09-26 と、ギャラリー https://claude.ai/artifact/UMNsKJJHdFsr5m3LuLsrmN に記録）

## 6. v4 との違い（対比）

| | v4 | v5 |
|---|---|---|
| 評価 | 5枚のカード（とても満足〜不満） | ★を5つ横に並べる（Googleと同じ体験） |
| 本文欄 | ②の話題と同じ画面に1つ（全員に見える） | 届け先のあとの書く画面に、**選んだ話題の数だけ** |
| 届け先 | 2枚の扉（押すと出口へ） | 2枚の扉の中に「文章も書く」（塗り）と「書かずに届ける」（線） |
| AI | 整える（押したときだけ・1文） | **つなげる**（書き終えたあとに1回。欄ごとに整えてつなげ、足した文字に色） |
| 「AI」の表示 | なし | 「AIがつなげました」のバッジ（既存の `AiBadge`） |

## 7. 本番化のときに決めること（未解決）

1. **レート制限を Supabase へ**：`/api/survey/polish` はサーバーの記憶で数えている（v4 からの宿題）。つなげるは欄の数だけ呼ぶので、上限の数え方も欄単位にする
2. **書いた文と届け先の保存**（B-3）：v4 の `supabase/0017_*`（未作成・承認項目 A-4）と一緒に設計する。欄ごと（話題ごと）に保存できると、お店側で「料理についての声」「接客についての声」を分けて読める
3. **Googleを開く**：試作は完了画面へ進むだけ。本番は `docs/specs/rating-flow.md` の Google 直リンク（place_id）を使う
4. **iPhone の実機で**、欄が3つ以上のときの縦の長さと、キーボードを開いたときの主ボタンの見え方を確かめる
5. **LP の書き換え**：「AIが下書きを用意」カード・FAQ・料金の「AI下書き」（壁打ち資料 §7）。「AIがつなげる。足したのは色の付いた文字だけ」が見出しの候補になる
