## 1. 一文の定義

> **全員が答えるのは★と話題の2問だけ。届け先を選んだあと、書きたい人にだけ「書く画面」を渡し、
> そこではAIが「続きを聞く」。AIは問いを出すだけで、公開される文の中身は100%本人の言葉にする。**

## 2. 2026-09-26 に決まったこと（天真）

| # | 論点 | 決定 |
|---|---|---|
| 1 | ★だけの強調をどこでするか | **Googleの扉の中で行う。** 2枚の扉（Googleに投稿／お店にだけ）は同じ形・同じ強さ。LP「2つの扉は同じ重さ」を守る |
| 2 | 書く画面のAI | **A1 続きを聞く＋A2 手が止まったら問いを変える＋B1 整える（v4）＋C1 キーボードのマイク案内**（壁打ち資料の「標準」） |
| 3 | 例の予測変換（続きの文をAIが出す） | **入れない**（実測で21回中21回が本人の書いていない内容を足し、低評価は3回とも満足の話に変わった） |
| 4 | 来店客の画面で「AI」と名乗るか | **問いの頭に小さく「AI」と付ける** |
| 5 | お店にだけの扉にも書く画面を置くか | **置く。** 書く画面は1つで、届け先だけが違う |

## 3. 画面と流れ

```
① 評価（5択・タップで自動で次へ）
② 話題（当てはまるもの・いくつでも・選ばなくても進める）→［次へ］
③ 届け先（2枚の扉。同じ大きさ・同じ形・同じ言い方。並び順は★によらず固定）
     ┌ Googleマップに投稿／だれでも読めます ─┐   ┌ お店にだけ届ける／お店の人だけが読みます ┐
     │［★だけで投稿する］（主ボタン）        │   │［このまま届ける］（主ボタン）            │
     │  文章も書く ›                          │   │  文章も書く ›                            │
     └────────────────────┘   └─────────────────────┘
④a ★だけ：Googleの画面で★を選んで「投稿」を押すと完了です →［Googleマップを開く］
④b 書く画面（両方の扉で共通。届け先の表示と主ボタンだけが違う）
④c お店へ（このまま）：お店にとどく内容（評価・選んだこと）→［とどける］
⑤ 完了
```

**タップ数（v4 と同じ数え方）**

| 経路 | タップ数 |
|---|---|
| ★だけでGoogleへ | 4（評価・次へ・★だけで投稿する・Googleマップを開く） |
| そのままお店へ | 4（評価・次へ・このまま届ける・とどける） |
| 書いてGoogleへ／書いてお店へ | 4＋書く画面の操作（文章も書く・主ボタン） |

2つの出口の最短タップ数が同じ（4）なのは v4 から引き継いだ意図（案Iの「2枚の扉の重さが同じ」を数で担保する）。

**④b 書く画面の要素（上から）**

1. ‹ もどる ／ 届け先：Googleマップ（だれでも読めます）または お店だけ（お店の人だけが読みます）
2. 見出し「あなたの言葉で」
3. 本文欄。プレースホルダは v4 の**静的な問い**（話題ごとに3問を回す）。**白紙のあいだAIは呼ばない**
4. AIの問い（§4）。頭に「AI」。押すと本文欄にカーソルが戻るだけで、**問いは本文に入らない**
5. 「ここまでで投稿できます」（§4 A2 の出口）
6. ［整える］（v4 と同じ条件で現れる）／ マイクの案内「キーボードのマイクで、話しても書けます」
7. 整えるの候補（灰色の1文。タップで採用・もどす）
8. 注記：単語を並べるだけで大丈夫／個人が特定できることは書かない／（Googleのとき）書いた文章は、お店にも届きます
9. 画面下に固定の主ボタン：Google は「コピーしてGoogleを開く」（本文が空なら「Googleマップを開く」）、お店は「お店にとどける」

## 4. 続きを聞く（A1）と、手が止まったら問いを変える（A2）

**1文字ごとには呼ばない。手が止まったら呼ぶ。** 1回に約1秒かかるので、1文字ごとだと打つ速さに追いつかない。

| 条件 | 値 | 置き場 |
|---|---|---|
| 呼ぶまでに手が止まっている時間 | 1.5秒（日本語入力の**変換中は数えない**） | `ASK_IDLE_MS` |
| 本文の長さ | 4字以上・60字未満（十分書けたら聞かない） | `ASK_MIN_CHARS` / `ASK_STOP_CHARS` |
| 前の問いのあと書き足す量 | 6字以上（答える間を奪わない） | `ASK_GAP_CHARS` |
| 1人に出す問い | 3つまで（頼む回数は検査落ちを含めて5回まで） | `ASK_MAX_SHOWN` / `ASK_MAX_ATTEMPTS` |
| A2：問いのあと何も打たない時間 | 10秒 → 別の角度の問いに1回だけ替える → さらに10秒で「ここまでで投稿できます」 | `ASK_STUCK_MS` |
| 打ち始めたら | 問いは消す。A2 と出口の案内も最初から | `useAskQuestion` |
| 整えるの候補が出ている間 | 問いは引っ込める | 同上 |

- 数値はすべて `components/survey/useAskQuestion.ts` の先頭にある。実機の触り心地で調整する前提
- 壁打ち資料では「0.8秒」と書いたが、**変換の合間の短い停止で問いが出ては消えるのを避けるため 1.5秒にした**

**AIに渡すもの：本文の文字列と、直前に出した問い（最大3件）だけ。** ★・話題タグ・店名・メニュー名は API の型に無い
（`app/api/survey/ask/route.ts`）。直前の問いを渡すのは、A2 で「別の角度」を頼むためと、同じ問いの繰り返しを検査で止めるため。

## 5. 検査（AIの自己申告を信じない）

`lib/survey/ask-guard.ts`。1つでも落ちたら問いを捨て、**画面には何も出さない**。落ちたときはサーバー側で**1回だけ頼み直す**（落とす基準は緩めない）。

- 問いは1つだけで「？」で終わる。32字以内。1行
- **開いた問い**だけ（何・どんな・どの・どう・どこ…を含む、または「〜ことは？」）。「海は見えましたか？」のような、はい／いいえの問いは捨てる。
  「何か〜ありますか？」「何か〜しましたか？」も実質はい／いいえなので捨てる
- 評価の言葉（よい・おいしい・丁寧・工夫・配慮・参考に・助か…）が無い。**本人が本文に書いた語ならなぞってよい**
- どのお店かを聞かない（「どこでパスタを食べましたか？」は捨てる。「どこで待ちましたか？」のような店の中の場所は通す）
- 年齢・名前など個人のことを聞かない／前置きや謝罪が無い／直前の問いと同じでない

必須テスト：`npm run survey:ask-guard`（30件。通す側・捨てる側とも、2026-09-26 に本物の Haiku が返した問いを含む）。
⚠ Node のTS直読みを使うので `npm run check` には入れていない（`survey:guard` と同じ扱い）。

## 6. 整える（B1）・話して書く（C1）

- **整える**は v4 のまま（`/api/survey/polish`・`polish-guard.ts`）。ボタンの名前だけ「文にする」→「整える」
- **話して書く**は、キーボードのマイクの案内だけ。Claude は音声を直接受け取れないので、録音ボタンは作らない

## 7. 実測（2026-09-26、/demo/v5 を検品用ビルドで実際に操作）

| 確かめたこと | 結果 |
|---|---|
| 最初の問い | 最後の入力から約2.5〜2.8秒で出る（待ち1.5秒＋AI約1秒）。例「今日は天気が良く窓際の席だったので」→「窓からはどんな景色が見えていましたか？」 |
| 打ち始めたら消えるか | 消える（問いの数 0） |
| 書き足したあとの次の問い | 「〜 海が見えた 船がゆっくり通ってた」→「その海を見ながら、どんな気分でしたか？」 |
| A2 | 「どんなことを説明してくれましたか？」→ 約12秒後「その説明を聞いて、どう思いましたか？」→ さらに約10秒後「ここまでで投稿できます」 |
| お店の扉から書く | 「待ち時間が長かった」→「待っている間、何をしていましたか？」。主ボタンは「お店にとどける」 |
| 整える | 「パスタ もちもち ソース濃いめ」→「パスタはもちもち、ソース濃いめ。」、タップで本文に入る |
| 途中で見つけて直したこと | ①長い書きかけで3回に1回ほど問いが30字を超えて捨てられ、2つ目の問いが出なかった → プロンプトを「20字くらい」にし、上限を32字、検査落ちは1回だけ頼み直す ②入れ替えで「何か参考になったことはありますか？」（良い前提＋実質はい／いいえ）が出た → 検査で捨てるようにした ③最終の撮影で「何か行動に移しましたか？」が出た → 「何か〜しましたか？」の形も捨てるように広げた（必須テスト30件） |

費用は問い1回あたり約0.1円（頼み直しが起きても約0.2円）。

## 9. 本番化のときに決めること（未解決）

1. **レート制限を Supabase へ**：いまはサーバーの記憶で数えている（`/api/survey/polish` と同じ宿題）
2. **書いた文と届け先の保存**（B-3）：v4 の `supabase/0017_*`（未作成・承認項目 A-4）と一緒に設計する
3. **Googleを開く**：試作は完了画面へ進むだけ。本番は `docs/specs/rating-flow.md` の Google 直リンク（place_id）を使う
4. **iPhone の実機で日本語入力を確かめる**：変換の確定（compositionend）の順番は端末で違うことがある。検品は Playwright（変換イベントなし）でしか通していない
5. **問いの質の見張り**：「どんな気分でしたか？」「どう思いましたか？」は評価語を含まないので通しているが、感情を聞く問いが多すぎないかは5人テストで見る。
   また「その船はどのくらいの時間かけて通っていきましたか？」のように、**害は無いが細かすぎる事実**に向かう問いが出ることがある（最終の撮影で1回）。プロンプトの調整は実機で触ってから
6. **LP の書き換え**：「AIが下書きを用意」カード・FAQ・料金の「AI下書き」（壁打ち資料 §7）
