**「洋輔さんの YORKYS BRUNCH 夙川店で、実際のお客様が卓上POPのQRを読んで回答し、
その結果を管理画面で見られる」** 状態を最初のゴールとします（＝フェーズ4の完了）。

## 2. 決定事項（2026-08-05 天真）

### ① Googleレビュー増加数の指標はやめる → **Figma・コードとも反映済み（2026-08-05）**

管理画面のKPIから「Googleレビュー増加」を外し、**「Googleへ送客した数」だけにする。**
**KPIの3枚目は「送客率」**（2026-08-05 天真決定）。

- 理由：Google側の実際のレビュー件数は、GOOD REVIEW からは取得できない
  （取るにはGoogle Business Profile APIでの店舗ごとの連携許可が要り、実装も重い）
- **Figma側も直す。** トップ画面のKPIカード・「Googleレビュー増加数の推移」グラフ・
  店舗別内訳テーブルの列・店舗詳細画面が対象。PC / SP の両方
- Figma に `Ref / KPI 実投稿率（データが取れる場合の差し替え案）`（`50:872`）という
  参照フレームがあるが、これも同じ理由で採用しない
- 設定（通知）の「新しいGoogleレビュー」も同じ理由で実現できないため、**削除した**
  （2026-08-05 天真決定。Figma の PC / SP とも反映済み）

### ② アンケートのタグは店舗側が編集できるようにする

**Figma に既に設計がある**（`設定（アンケート項目）` PC `73:1294` / SP `75:1699`）。

- 業態テーマごとにプリセットを用意し、店舗が自由に編集できる。**各 最大8個**
- 「良かった点（★5・4）」「改善点（★3・2・1）」の2グループ
- 「プリセットに戻す」ボタンがある
- ⚠ 現状のコードはタグが直書き（`GOOD_TAGS` / `IMPROVE_CHECKLIST`）で、
  しかも飲食店の語彙しか無い。**DBの持ち方を変える必要がある**（4-B参照）

### ③ 最初に実地投入する店舗は「YORKYS BRUNCH 夙川店」

- 業態テーマ：`restaurant`（飲食店）
- スラッグ案：`yorkys-shukugawa`（`docs/specs/rating-flow.md` E-10 の命名規則に沿う）
- **テストデータではなくこの店舗を前提に、テナント・店舗のデータを作る**
